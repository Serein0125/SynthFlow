# SynthFlow · 预生成式 AI 编程工作台

> 你还在打字，代码已经在写了。
> 不是"输入 → 点发送 → 等回复"，而是**边说边生成**：AI 与你的输入同步思考、同步产出、同步给建议，你随时改前文，它只做增量。


## 它到底哪里不一样

| 传统 AI 编程（Copilot / Cursor Tab / Trae / 各类 Agent） | SynthFlow |
| --- | --- |
| 敲代码后提示几行，按 Tab 采纳 | 敲**需求**时就流式生成整个功能 |
| 一句话提交 → 等回复 → 看结果 | 不提交、不等待，打字即生成，全程不中断 |
| 生成时你只能看着 | 生成的同时并行思考，主动推可采纳的建议给你 |
| 一次对话改一个文件 | 自动建目录/多文件，改动实时跳转到对应代码 |
| 改前文 = 推倒重来 | 自动判断：增量补丁 / 增量续写 / 才重生成 |
| 想撤销靠手写 git | 一键回退到"这句话还没输入时"的版本 |

四个真正稀缺的能力，SynthFlow 都做了实现：

1. **预演（Speculation）**：你停顿 0.3 秒，它就开始生成，但**先不落盘**。等你被判定"写完了"，直接**采纳预演结果**——
   省掉一次完整模型调用（省钱 + 更快）。如果你在预演期间又改了需求，它会丢掉过期结果、改走增量。
2. **意图完整度判定**：不是简单 debounce。用 10+ 个信号（句末标点、连接词结尾、括号/围栏闭合、动作词、打字停顿、
   增长趋势…）算出一个 0~1 的分数，界面上**实时显示**它为什么认为你还没写完。停手不打了还会兜底开工。
3. **上下文锚定式增量**：改前文中间的一段时，它把"改掉了什么 / 新要求是什么"变成定点补丁指令，
   并把最近碰过的文件作为锚点一并塞进上下文，明确要求模型**只动受影响的文件**。
4. **版本链 + 一键回退**：每一轮生成前后各打一次全量快照，"回退一步"同时回滚**文件**和**提示词**。

### 值得亲手试一遍的三件事

1. **只打半句就停**：输入 `帮我写一个后台管理系统，包含` → 别动。你会看到右侧开始流出思考、代码开始在编辑器里长出来，
   但左边**没有产生版本**——因为它在预演。补上 `用户列表、搜索和分页。`，它会直接把预演结果落盘（提示"预演结果被直接采纳"）。
2. **改前文**：把提示词里的 `蓝色主题` 改成 `暗色主题`，观察底部提示"策略：定点增量补丁"，右侧只会出现涉及文件的补丁块，
   其它文件原样不动。
3. **`Alt+Z` 回退**：文件与提示词一起回到上一句话之前。再按一次继续往前退。

## 接真实模型

三种方式任选（优先级：环境变量 > 界面设置 > 配置文件）：

**A. 界面（推荐）**：右上角「⚙ 设置」→ 选服务商 → 填模型名 / Base URL / API Key → 保存并生效。
Key 只写入本机 `D:\ProgramData\SynthFlow\.synthflow\config.json`，不会外发到任何地方。

**B. 环境变量**（适合写进脚本）：

```bat
set SYNTHFLOW_PROVIDER=deepseek
set SYNTHFLOW_API_KEY=sk-你的key
set SYNTHFLOW_MODEL=deepseek-chat
npm start
```

**C. 配置文件** `.synthflow/config.json`：

```json
{
  "provider": "deepseek",
  "baseUrl": "https://api.deepseek.com/v1",
  "model": "deepseek-chat",
  "temperature": 0.3,
  "maxTokens": 4096,
  "specDelayMs": 320,
  "commitIdleMs": 900,
  "settleMs": 1600,
  "intentThreshold": 0.6,
  "autoCommit": true,
  "autoAdoptHigh": false
}
```

内置预设：`mock`（离线）· `deepseek` · `openai` · `ollama`（本地模型，不花钱）· `siliconflow` · `custom`（任意 OpenAI 兼容端点）。

### 省钱建议（你余额不多，这几条很重要）

- **默认就是 `mock`**，不配置就一分钱不花，交互体验完全一致。
- **预演采纳机制本身就在省钱**：一次输入通常只调用模型 **1 次**（预演被直接采纳），而不是"预演 + 提交"2 次。
- 把「预演延迟」调大（如 600ms）能减少你打字过程中的无效调用。
- 想彻底零成本地跑真实模型：装 Ollama，`provider` 填 `ollama` + `qwen2.5-coder:7b`。
- 每次生成的实际耗时、生成字符数都会记进 `.synthflow/memory/profile.json`，可以自己核对调用次数。

## 它是怎么工作的（简版）

```
你打字  ──每 180ms 上报──▶  POST /api/input
                              │
                     analyzeIntent()   ──▶  SSE: intent（界面实时显示判定理由）
                     decidePromptChange() ─▶  增量 / 续写 / 重生成
                              │
              ┌───────────────┴────────────────┐
     ~320ms 后预演                     判定完成后 900ms 提交
     （不落盘，可被丢弃）                （优先直接采纳预演结果）
              │                                │
              └──────────► 模型流式输出 ◄───────┘
                              │
        <<<SF think>>>  <<<SF suggest>>>  <<<SF file ...>>>
                              │
                   增量解析器边收边推 SSE
                              │
        前端：思考面板 / 建议卡片 / 代码实时增长 / 自动跳转文件
                              │
                     提交时：Δ文件 → 沙箱 → 快照 → 版本
```

详细设计（协议语法、判定公式、并发与取消、错误恢复）见 **`docs/DESIGN.md`**；
开源方案借鉴与差异见 **`docs/RESEARCH.md`**。

## 已知边界（不吹牛）

- **内置演示模型**只会按关键词产出 4 类模板（后台管理 / 登录 / 图表 / 表单 / 通用小工具）。
  它存在的意义是让你零成本验证交互链路；真实代码质量取决于你接的模型。
- **补丁未命中**时会明确提示"补丁未命中：xxx"，并保留其它文件的改动，不会静默改坏文件。
  模型写错 SEARCH 片段是行业通病，这里做了三层兜底（精确 → 忽略首尾空白/行归一 → 首行锚点）。
- **回退是线性版本链**：`回退一步` 反复按可以一路退到空项目；暂不支持分叉/重做（redo）。
- **RAG 是词法检索（BM25）**，不是向量检索：零依赖、零下载、够用，但对语义改写不敏感。
- 前端目前是**工作台形态**（浏览器内），不是 VS Code 插件。插件化需要额外的 IDE 宿主环境，
  在没有你本机配合的情况下不适合半夜自动推进——这一条留给你醒后决定方向。
