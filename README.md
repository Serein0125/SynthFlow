# SynthFlow · 预生成式 AI 编程工作台

> 你还在打字，代码已经在写了。
> 不是"输入 → 点发送 → 等回复"，而是**边说边生成**：AI 与你的输入同步思考、同步产出、同步给建议，你随时改前文，它只做增量。

## 它到底哪里不一样

| 传统 AI 编程（Copilot / Cursor Tab / Trae / 各类 Agent） | SynthFlow |
| --- | --- |
| 敲代码后提示几行，按 Tab 采纳 | 敲**需求**时就流式生成整个功能 |
| 一句话提交 → 等回复 → 看结果 | 不提交、不等待，打字即生成，全程不中断 |
| 生成时你只能看着 | 生成的同时并行思考，主动推可采纳的建议给你 |
| 一次对话改一个文件 | 自动建目录/多文件，改动实时跳转到对应代码 |
| 改前文 = 推倒重来 | 自动判断：增量补丁 / 增量续写 / 才重生成 |
| 想撤销靠手写 git | 一键回退到"这句话还没输入时"的版本 |

四个真正稀缺的能力，SynthFlow 都做了实现：

1. **预演（Speculation）**：你停顿 0.3 秒，它就开始生成，但**先不落盘**。等你被判定"写完了"，直接**采纳预演结果**——
   省掉一次完整模型调用（省钱 + 更快）。如果你在预演期间又改了需求，它会丢掉过期结果、改走增量。
2. **意图完整度判定**：不是简单 debounce。用 10+ 个信号（句末标点、连接词结尾、括号/围栏闭合、动作词、打字停顿、
   增长趋势…）算出一个 0~1 的分数，界面上**实时显示**它为什么认为你还没写完。停手不打了还会兜底开工。
3. **上下文锚定式增量**：改前文中间的一段时，它把"改掉了什么 / 新要求是什么"变成定点补丁指令，
   并把最近碰过的文件作为锚点一并塞进上下文，明确要求模型**只动受影响的文件**。
4. **版本链 + 一键回退**：每一轮生成前后各打一次全量快照，"回退一步"同时回滚**文件**和**提示词**。

### 关于目标项目（这是 v3 最实用的部分）

设置 → 项目与风格 → 填一个目录 + 选「暂存模式」。之后：

- **读**：合并视图，暂存层优先，否则读你的项目真实内容 —— 所以模型能看到你真实的代码、真实的风格、真实的组件名（实测它自己引用了项目里的 `ActivityCard`/`PostCard`/`CommentSection`）
- **写**：只写暂存层，你的项目一动不动
- **应用**：确认后才写入（会先打快照，随时可回退）
- 每个目标项目有**独立的快照/会话/暂存目录**（`.synthflow/projects/<名字>-<hash>/`），切换项目不会互相污染

### 值得亲手试一遍的四件事

1. **只打半句就停**：输入 `帮我写一个后台管理系统，包含` → 别动。1 秒后右侧开始流出思考、代码开始在编辑器里长出来，
   但左边**没有产生版本**——因为它在预演。补上 `用户列表、搜索和分页。`，它会直接把预演结果落盘（提示"预演结果被直接采纳"，省掉一次调用）。

## 接真实模型

三种方式任选（优先级：环境变量 > 界面设置 > 配置文件）：

**A. 界面（推荐）**：右上角「⚙ 设置」→ 选服务商 → 填模型名 / Base URL / API Key → 保存并生效。
Key 只写入本机 `D:\ProgramData\SynthFlow\.synthflow\config.json`，不会外发到任何地方。

**B. 环境变量**（适合写进脚本）：

```bat
set SYNTHFLOW_PROVIDER=deepseek
set SYNTHFLOW_API_KEY=sk-你的key
set SYNTHFLOW_MODEL=deepseek-chat
npm start
```

**C. 配置文件** `.synthflow/config.json`：

```json
{
  "activeProfileId": "p_default",
  "profiles": [
```

### 省钱建议（这几条很重要）

- **预演采纳机制本身就在省钱**：完整句子直接生成（跳过预演）；半截需求停顿后预演，判定写完时**直接采纳预演结果**，
  一次输入通常只调用模型 **1 次**，而不是"预演 + 提交"2 次。
- **状态栏实时显示用量**：`本轮 ≈N tokens · 累计 M 次调用 · X tokens`。接真实模型时优先使用接口返回的**真实 usage**，
  不是估算值——你能直接看到每次改动花了多少。
- **预演延迟**默认 1000ms。调大（如 1500ms）会进一步减少打字过程中的调用；调小会更"跟手"但更费。
- **补丁未命中自动重试**默认开启，会多消耗一次调用；余额紧张时可以关掉。
- 想彻底零成本地跑真实模型：装 Ollama，`provider` 填 `ollama` + `qwen2.5-coder:7b`。
- 每次生成的耗时、token 数都记进 `.synthflow/memory/profile.json`，可以自己核对。

## 已知边界（不吹牛）

- **Monaco 是唯一的外部依赖**（约 25 MB）。如果它加载失败（文件被删、CSP 限制），编辑器会自动降级为只读高亮，
  其余功能不受影响；`/selftest.html` 会明确告诉你哪一步挂了。
- **暂存模式只保护"写入"，不保护"读取"**：切到真实项目后 SynthFlow 会读你的代码（做风格扫描与检索），
  这是它贴齐风格的前提。不想让它读就把目标目录指回 `workspace/`。
- **应用改动是覆盖式的**：确认时会用暂存内容覆盖项目里的同名文件，不会自动合并冲突。所以默认是暂存模式。
- **内置演示模型**只会按关键词产出几类模板。界面上已移除，只用于离线回归测试。
- **补丁未命中**会明确提示并**自动重试一次**；仍失败则保留其它文件的改动，不会静默改坏文件。
  兜底策略是三层：精确 → 忽略首尾空白/行归一 → 首行锚点。
- **版本链是线性的**：可以来回回退/前进，但在历史版本上继续生成会**丢弃右侧分支**（会提示丢弃了几个版本）。
- **"待确认版本"只是标记，不是延迟写入**：文件当轮就落盘了，确认动作决定的是"保不保留为一个版本"。
- **RAG 是词法检索（BM25）**，不是向量检索：零依赖、零下载、够用，但对语义改写不敏感。
- **思考折叠、布局、主题、差异视图偏好**存在 localStorage，换浏览器会回到默认。
- 前端仍是**工作台形态**（浏览器内），不是 VS Code 插件。
